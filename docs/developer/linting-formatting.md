# Linting & Formatting (oxlint + oxfmt via Vite+)

This project uses **Vite+** as its unified toolchain. Linting is **oxlint** and
formatting is **oxfmt**; both replaced Biome, and both are configured inside
`vite.config.ts` rather than in their own dotfiles.

> Migrated from Biome. `biome.json` and `@biomejs/biome` are gone, and the ~330
> `// biome-ignore` comments were removed — 313 of them suppressed
> `useNamingConvention`, a rule oxlint has no equivalent for.

## Quick commands

```bash
bun run lint          # vp lint
bun run lint:fix      # vp lint --fix
bun run format        # vp fmt . --write
bun run format:check  # vp fmt . --check
bun run check         # vp check — format + lint in one pass
bun run check:all     # full gate: typecheck, lint, ast-grep, format, Rust, tests
```

`vp` ships as a `bin` of the local `vite-plus` dependency, so no global install
is required. (The global CLI — `curl -fsSL https://vite.plus | bash` — is only
needed for out-of-project commands like `vp create`.)

## Configuration

Both live in `vite.config.ts`. Vite+ explicitly recommends against separate
`.oxlintrc.json` / `.oxfmtrc.json` files.

```ts
export default defineConfig(({ mode }) => ({
  lint: {
    ignorePatterns: toolingIgnorePatterns,
    options: {
      typeAware: true,  // rules that need type information
      typeCheck: true,  // full tsc diagnostics via tsgolint
    },
  },
  fmt: {
    ignorePatterns: ['**/*.md', ...toolingIgnorePatterns],
    singleQuote: true,
    jsxSingleQuote: false,
    semi: true,
    trailingComma: 'es5',
    printWidth: 100,
    tabWidth: 2,
    endOfLine: 'lf',
  },
}));
```

The `fmt` values deliberately mirror the old `biome.json` style so the one-time
reformat stayed small.

### Ignored paths

`toolingIgnorePatterns` covers generated files (`src/lib/bindings.ts`,
`src/routeTree.gen.ts`, `src/locales/**/messages.ts`), build output, and the
agent/worktree directories (`.claude/**`, `.worktrees/**`, …) — those hold
nested checkouts of this same repo, and formatting through them would rewrite
files belonging to another branch.

Markdown is excluded from `fmt`, matching the old `biome.json` override.
`CHANGELOG.md` is generated by release-please and would churn on every release.

### Type-aware linting

`typeAware: true` enables the rules that need type information
(`no-floating-promises`, `unbound-method`, `no-base-to-string`, …), and
`typeCheck: true` additionally runs full `tsc` diagnostics through tsgolint.

Both are on. Getting there needed the tooling files outside `src/` to have a
tsconfig of their own — oxlint discovers the **nearest `tsconfig.json`** per
file, and previously `e2e/` and `scripts/` fell back to the root config, which
neither includes them nor supplies node/bun types:

| Path                                        | Governed by                                          |
| ------------------------------------------- | ---------------------------------------------------- |
| `src/**`                                     | `tsconfig.json`                                       |
| `e2e/**`, `scripts/**`                       | `e2e/tsconfig.json`, `scripts/tsconfig.json` → `tsconfig.tools.json` |
| `vite.config.ts`, `playwright.config.ts`, `lingui.config.ts` | `tsconfig.node.json` (referenced from the root config) |

`bun run typecheck` runs both projects (`tsc --noEmit && typecheck:tools`), so
the tooling code is type-checked for real rather than only incidentally by the
linter.

## Current state

`vp lint` exits 0 with **0 errors and ~239 warnings**. The warnings are rules
Biome never enforced, dominated by:

| Rule                   | Count | Notes                                            |
| ---------------------- | ----- | ------------------------------------------------ |
| `no-floating-promises` | ~199  | Genuine backlog; add `void` or handle rejections. |
| `unbound-method`       | ~19   | Mostly `vi.fn()` references in tests.             |
| others                 | ~21   | `no-new-array`, `no-base-to-string`, …           |

Warnings do not fail the build. Working the `no-floating-promises` backlog down
is worthwhile but was left out of the migration to keep the diff reviewable.

## Editor

Install the **oxc** VS Code extension (`oxc.oxc-vscode`); it is in
`.vscode/extensions.json`. `.vscode/settings.json` sets:

```json
{
  "oxc.fmt.disableNestedConfig": true,
  "editor.defaultFormatter": "oxc.oxc-vscode",
  "editor.formatOnSave": true
}
```

`disableNestedConfig` makes format-on-save use the root `fmt` block rather than
any nested config it might discover.

## Git hooks

`lefthook.yml` runs `vp fmt --write` and `vp lint --fix` over staged files on
pre-commit (with `stage_fixed: true`), and `vp lint` across the repo on
pre-push. See [Git Hooks](./git-hooks.md).

## Suppressing a rule

oxlint uses ESLint-style comments:

```ts
// oxlint-disable-next-line no-floating-promises
doSomethingAsync();
```

Prefer fixing over suppressing, and always say why in a trailing comment.
